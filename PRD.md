## 1. Discovery Brief & User Problem Definition

### 1.1 Target Users & Jobs-to-be-Done (JTBD)
- **Primary Persona:** Senior Product Managers, Heads of Growth, Startup Founders, and Product Operations Leaders.
- **Job-to-be-Done:** 
  > *"When I am framing a critical product strategy, designing growth loops, setting pricing, or diagnosing onboarding drop-off, I want to query the world's best product operators' verified frameworks, so that I can make high-conviction decisions, draft executive briefs, and generate interactive tools in minutes rather than spending dozens of hours searching through podcasts."*
- **Core User Friction Removed:**
  1. **Audio Discovery Friction:** Lenny's library spans 279+ episodes and hundreds of hours of conversation. Finding exact guest recommendations (e.g., Gustaf Alströmer on PMF metrics, Elena Verna on B2B viral loops, or Shreyas Doshi on LNO tasks) previously required manual scrubbing or fuzzy search.
  2. **Hallucination & Lack of Trust:** General LLMs often fabricate startup advice, attribute quotes to the wrong guest, or blend contradictory strategies.
  3. **Format Translation Gap:** PMs need structured outputs (1,250-word Ship 30 atomic essays, decision memos, and interactive calculators) rather than walls of unstructured chatbot text.

## 3. Assumptions & Trade-Offs

### 3.1 Key Engineering Assumptions
1. **Local-First Evaluation:** Evaluators may run the application offline or on laptops with varying GPU/RAM resources; local Ollama (`llama3.2`) and an offline grounded fallback engine must work seamlessly without requiring API keys.
2. **Transcript Stability:** The 279 transcript source repository represents a static high-quality dataset that can be chunked into deterministic 4,389 passages with pre-calculated lexical and semantic indices.
3. **Untrusted Artifact Generation:** Any HTML/CSS/JS generated by an LLM is treated as potentially adversarial and must be isolated from the parent DOM, auth tokens, and cookies.

## 5. Risks & Mitigation Matrix

1. **Hallucination Risk:** Mitigated by strict prompt constraints and RAG verification where every factual claim is anchored to a guest quote and timestamp.
2. **Local Model Hardware Constraints:** Mitigated by supporting lightweight quantized models in Ollama (`llama3.2:1b/3b`) with instant fallback to the built-in Grounded Engine.
3. **Artifact Security / XSS:** Mitigated by `ArtifactSecurityPolicy` rejecting `window.parent`, `document.cookie`, `localStorage`, and enforcing strict iframe isolation.
4. **Data Isolation:** Mitigated by PostgreSQL / SQLite session ownership checks ensuring guest and user discussions remain strictly segregated.

## 6. Functional Acceptance Criteria

1. **Grounded Chat:** User asks about PMF, retention, or growth; assistant returns detailed analysis with guest name, quote, episode title, and clickable YouTube timestamp.
2. **Out-of-Domain Guardrail:** User asks an unrelated topic (e.g. quantum physics); assistant politely states the topic is not covered in Lenny's Podcast transcripts.
3. **Ship 30 Skill:** Generates ~1,250-word essay featuring hook, modular H2 pillars, quotes, checklist, and golden takeaway.
4. **Interactive Artifacts:** Side-by-side rendering of interactive PMF diagnostic calculators, prioritize matrix, and frameworks.
5. **Session Persistence:** Starting a new chat or switching sessions retains conversation history across reloads.
6. **Authentication & Profile:** User can sign up, log in, view their workspace, and preserve all conversation history.
